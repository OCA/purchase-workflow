``purchase_request`` puts a smart button on the request pointing at the
purchase orders it produced. Nothing goes the other way: from an RFQ, or from
the vendor bill that followed it, there is no way back to what was originally
asked for and by whom.

This module adds that return path, as a smart button on the purchase order
and on the vendor bill.

On a bill the requests are collected through every purchase order line the
bill was built from, so a bill consolidating several orders reaches the
requests of all of them.

Usage
=====

Open a purchase order raised from a purchase request, or a vendor bill made
from such an order. A *Requests* button appears in the button box, with the
number of purchase requests behind the document.

The button opens the request directly when there is only one, and the list
when there are several. It stays hidden on documents with no purchase request
behind them.

Known issues / Roadmap
======================

* The count is computed on the fly rather than stored, so it cannot be used
  in a search filter or grouped on.
* Refunds reach the requests through the lines they carry. A credit note
  written from scratch, with no link to a purchase order line, shows no
  button.
